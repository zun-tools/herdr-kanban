# かんばん（Herdr app の mod）

YouTube「ずんだもんの実験道具箱」の動画【herdr入門⑤】欲しい画面は、頼むだけで作れるのだ（2026-11）で、AI に頼んで作ったかんばんを、ほかのプロジェクトでも使えるように整えた物です。動画の時点（2026-10-31）の版で、公開後は動画と同じ中身を保ちます。

プロジェクトのタスクを、工程ごとの列に並べて見せるかんばんです。各工程には担当（Claude Code や agy など）がいて、タスクは担当から担当へ受け渡されます。人が決める所（承認）では、カードが赤く「要対応」になって止まります。

- `mods/kanban` : かんばん本体（列・カード・全体の進み具合・タスクの追加・担当の起動）
- `mods/kanban-detail` : カードを押すと開く詳細のポップアップ（工程ごとのファイルの中身と担当の状態）
- `example/.kanban` : プロジェクトに置く設定のひな形

動作確認は Herdr.app 0.1.10 です。

## 入れ方

1. `mods/kanban` と `mods/kanban-detail` を、Herdr の mods フォルダ（`<appHome>/mods/`）へコピーします。
2. 自分のプロジェクトのフォルダに `example/.kanban` をコピーします（`<プロジェクト>/.kanban/config.json` と `roles.md` ができます）。
3. かんばんを開くときの props にプロジェクトを渡します。

   ```json
   {"project": "~/work/myapp"}
   ```

   props を渡さずに開くと、従来どおり `mods/kanban/config.json` を読みます（その場合の `work_dir` は必須で、タスクは `<work_dir>/tasks/`、`roles.md` は `<work_dir>/roles.md`）。

## 置き場所

```
<プロジェクト>/.kanban/
  config.json      工程と担当の設定
  roles.md         各担当へ送る役割（ひな形）
  tasks/
    T1/            タスク1つ=フォルダ1つ
      task.md      タスクの内容（入力欄に書くと作られる）
      state        いまの工程と状態の1行
      design.md …  各工程が書くファイル
```

タスクはプロジェクトの作業ファイルと混ざらないよう、`.kanban/tasks/` に置きます（元の試作では `work/tasks/`）。`.kanban/` を git で管理するかは自由です（タスクの記録を残したくなければ `tasks/` だけ `.gitignore` へ）。

## 設定（config.json）

| キー | 意味 |
|---|---|
| `work_dir` | 担当を起動するフォルダ。省略するとプロジェクトのフォルダ。相対パスはプロジェクトからの相対 |
| `first_column` | 最初の列の名前（まだ誰も手を付けていないタスク） |
| `done.name` | 最後の列の名前（最後の工程が完了したタスク） |
| `stages` | 列の並び。`name`（工程名）・`files`（詳細に出すファイル。最後の1つが「その工程の完了」の目印）・`agent` |
| `agent.command` | 担当の起動コマンド（配列。`~` 可） |
| `agent.prompt_flag` | 最初の指示を渡すフラグ。`null` なら最後の引数 |
| `move_on` | そのファイルができたら、カードを指定の工程の列へ進める |
| `needs_action` | `when` のファイルがあり `unless` のファイルが無いとき、カードを赤く「要対応」にする |

担当の例:

```json
{"name": "Claude Code (haiku)", "command": ["claude", "--model", "haiku"], "prompt_flag": null}
{"name": "agy", "command": ["agy", "--mode", "accept-edits"], "prompt_flag": "-i"}
```

注意: Herdr 本体（herdr-core）から起こした端末では PATH に `claude` や `agy` が無いことがあります。起動しないときは `/Users/you/.local/bin/claude` のように絶対パスで書いてください。

## roles.md

担当を起動すると、工程ごとに「## 工程名」の節（と `## 共通`）が担当へ送られます。節の名前は config.json の工程名と同じにします。中身（何を読み、何を書き、誰に知らせるか）はひな形の例なので、自分の仕事に合わせて書き換えてください。文中の置き換え:

- `{work_dir}` : 作業フォルダ
- `{next}` : 次の工程の担当の宛先（`hc send {next} "…"` で知らせる）
- `{agent}` : その担当の名前（state に書く）

担当は `state` に「`<工程名> 作業中 <担当名>`」「`<工程名> 完了 <担当名>`」と書きます。かんばんはこの1行から列と担当の状態を決めます。

## 使い方

- 入力欄にタスクを1行書いて Enter: `T1`, `T2`… のフォルダができ、最初の工程の担当へ知らせます。
- 「担当を起動」: 工程の名前のタブを作って担当を起動し、役割を送ります。すでにあるタブには役割だけ送ります。
- カードを押すと詳細が開きます（中身が長いときはスクロールできます）。

## 承認の仕方

ひな形では、デザインレビューが終わると（`design_review.md` があり `approved` が無い）カードが赤く「要対応（承認待ち）」になり、そこで止まります。内容を見て進めてよければ、実装の担当へ人が `T1 進めて` と送ります。実装の担当は最初に `approved` ファイルを作り、これでカードが「実装とテスト」の列へ進みます（`move_on`）。承認を挟まない構成にしたいときは `needs_action` を消してください。

## 注意

- 担当は自動でコマンドを実行できる設定で動きます（`accept-edits` など）。信頼できるプロジェクトでだけ使ってください。
- roles.md は担当の行動を縛る文です。担当の権限は起動コマンドの側で決まる点に注意してください。
- 作り直したい場合は `RECIPE.md` を参照してください。
