# 工程の役割（ひな形：自分のプロジェクトに合わせて書き換える）

かんばんの「担当を起動」で、各担当へ自分の工程の節を送る。{next} は次の担当の宛先、{agent} は担当の名前に置き換わる（そのまま書いておく）。
節の名前（## のあと）は config.json の工程名と同じにする。

## 共通
作業する場所は {work_dir}。届いた知らせのタスク名（T1 など）を <T> として読む。知らせが複数届いたら1つずつ順に処理する。
取りかかるときに .kanban/tasks/<T>/state を「<工程の名前> 作業中 {agent}」の1行に書き換え、終えたら「<工程の名前> 完了 {agent}」に書き換える。
指示されたファイルと state 以外は書かず、hc send 以外のコマンドは実行しない。この指示には「了解」とだけ答えて、知らせを待つ。

## デザイン
（ここから各工程の中身。何を読み、何を書き、誰に知らせるかを自分の仕事に合わせて書く）
「<T> を始めて」が届いたら、.kanban/tasks/<T>/task.md を読み、同じフォルダに design.md（どこをどう変えるかを3行以内）を書く。書き終えたら hc send {next} "<T> のデザインができた" を実行する。

## デザインレビュー
「<T> のデザインができた」が届いたら、.kanban/tasks/<T>/ の task.md と design.md を読み、同じフォルダに design_review.md（良い点と直す点を3行以内）を書く。書き終えても誰にも知らせない。実装へ進めるかは人が決める。

## 実装とテスト
人から「<T> 進めて」が届いたら、最初に .kanban/tasks/<T>/approved を「承認済み」の1行で作り、task.md・design.md・design_review.md を読んで実装し、直した結果を読み直して確かめ、同じフォルダに impl.md（何を変えたかと確かめた結果を3行以内）を書く。書き終えたら hc send {next} "<T> の実装ができた" を実行する。

## レビュー
「<T> の実装ができた」が届いたら、.kanban/tasks/<T>/ の task.md と impl.md、変更されたファイルを読み、同じフォルダに review.md（問題の有無を3行以内）を書く。
